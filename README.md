# Assignment 3

The goal of Assignment 3 is to implement subtitles in the existing multi-threaded video player. The subtitles will be
added as a Frame Processor, which will be generated by calling out to an external cloud provider.

A few requirements come with this:

* A new command-line option: -S, --subtitle-frames Add speech-to-text subtitles to frames
* A new button to the right of the mute button to toggle subtitles on/off
* Toggle subtitles via the 's' key
* Real-time rendering of subtitles:
    * Legible subtitle text
    * Rendered with san serif white font with black outline
    * Text shouldn't exceed 42 characters per line
    * Text should not exceed 2 lines
    * Text for an entire phrase/sentence should appear on screen when spoken, remains no less than 1 second, no more
      than 7 seconds
    * Text is synchronised with dialogue at phrase and sentence level where possible
    * Linebreaks should occur after punctuation where possible.
* Subtitles are removed the instant they are toggled off
* Subtitles displayed as soon as practical when toggled on
* Toggling subtitles doesn't affect continuity of video playback
* Cloud API requirements:
    * Subtitles retrieved from `http://localhost:8080/api/v1/subtitles`
    * Web server must use `https://api.openai.com/v1/audio/transcriptions` to retrieve subtitles, using the whisper-1
      model and the verbose_json response format with both timestamp_granularities[]=word and timestamp_granularities[]
      =segment requested.
        * Subtitles are not expected to be displayed for segments returning noSpeechProb > 0.6 and aveLogProb < -1.0,
          otherwise they are
    * Cumulative total usage information from the transcription service must be tracked and reported in seconds
      via http://localhost:8080/api/v1/global/usage. A GET request on this end point is expected to return a single JSON
      structure { "usage": s } where s is a floating point number.
    * You may cache transcription data on your web server to prevent repeat media plays across multiple clients reusing
      the whisper-1 model to obtain both cost savings and timeliness gains when generating subtitles.

## Implementation plan

* Extend the Assignment 1 server with a subtitles endpoint that accepts original media audio and returns timed words and
  segments from Whisper. Track cumulative transcription usage in seconds and keep the API key on the server.
* Extract and upload audio in bounded chunks on background threads, keeping network requests separate from playback.
  Cache transcription results on the server and retain received subtitles in the player for seeking and network outages.
* Convert transcription results into timed subtitle cues, filtering low-confidence non-speech segments and splitting
  text at natural phrase boundaries to meet the line length, line count and display duration requirements.
* Add a subtitle frame processor that selects cues using media timestamps and draws white text with a black outline.
  Preserve a clean version of the displayed frame so subtitle toggles can redraw it immediately, including while paused,
  without restarting playback or leaving subtitles baked into queued frames.
* Connect the `-S` / `--subtitle-frames` option, subtitle button and `S` hotkey to the same subtitle state. Preserve
  effect ordering and both playback modes, and handle pause, seeking and replacement media without displaying stale
  cues.
* Add focused tests for cue timing and formatting, API responses, caching and usage accounting. Verify playback and
  immediate toggling under heavy effects, seeking, network loss and recovery, then document the design and results.
